Using the lab compute server

A one-time setup, about 30 minutes. After this you work on the M1 Max from your own laptop, and ask for analyses in plain English.

What this is

The lab M1 Max (64 GB RAM, 2 TB) will be sitting in the lab, always on. It holds a lot of reference database, AACR-GENIE, MSK-IMPACT, MSK-HEME, COSMIC, the human and mouse genomes, GENCODE annotations, and the environments for running our analyses.

You connect to it from your own machine. Everything runs on the server, so nothing large is ever copied to your laptop and nothing has to be installed there beyond a connection tool and an editor.

I have also summarized all kinds of analyses of mine and built them in a Claude Code skill, /bio-scientist, for you to use. You can prompt by "/bio-scientist, how common is DNMT3A R882H in AML?" to do analysis.

This will give you a step-by-step setup of how to run these analyses.

Your account on the server is fsr — you have your own home directory, and the shared reference data is readable by both of us.

Setup

  1. Install Tailscale and sign in

    Tailscale is how your laptop reaches the lab machine. It works from home, from the office, from a conference — no VPN, no IP addresses to remember.

    Download it from tailscale.com/download and install it. When it asks you to sign in, choose Sign in with Google and use the lab Gmail account — Kexin will give you the address and password.

    It has to be that account. All the lab machines live under it, so signing in with your MIT address or a personal Google account puts you in a different, empty network and m1max will not appear.

    Once signed in you should see m1max in the Tailscale menu.

  2. Check you can reach the server

    Open Terminal (⌘-Space, type "Terminal") and run:

    ssh fsr@m1max

    The first time it asks "Are you sure you want to continue connecting?" — type yes. You should land at a prompt on the server. Type exit to come back.

    If it says "tailnet policy does not permit you to SSH as user fsr", the access rule has not been applied yet — send Kexin that exact message.

  3. Save yourself the typing

    So that ssh m1max works on its own, run this on your laptop:

    cat >> ~/.ssh/config <<'EOF'

Host m1max
    HostName m1max
    User fsr
    ServerAliveInterval 60
EOF

    Now ssh m1max connects directly.

  4. Install VS Code and connect through it

    A terminal is fine for quick things, but for real work you want an editor: file browser, figures you can actually look at, notebooks.

    Install VS Code, then inside it install the Remote - SSH extension (⇧⌘X, search for it).

    Then press ⇧⌘P, type Remote-SSH: Connect to Host, and pick m1max. A new window opens — everything in it is running on the server, not your laptop.

    This is the part worth getting working. From here on, "open a terminal" means the terminal inside that VS Code window (⌃`).

  5. Install Claude Code and sign in

    In the VS Code terminal (connected to m1max):

    brew install --cask claude-code
claude

    At the Claude prompt, type /login and follow the link to sign in with your own Claude account. Everyone uses their own — your work and your history stay yours.

    This one is not the lab Gmail. Tailscale uses the shared lab account because that is what puts the machines on one network; Claude Code is per-person.

  6. Install the lab's skills

    Still in the server terminal:

    mkdir -p ~/Documents/GitHub && cd ~/Documents/GitHub
git clone https://github.com/kexindon/claude-bio-scientist.git
cd claude-bio-scientist
./install.sh

    Then tell the tools where the shared data lives:

    cat >> ~/.zshrc <<'EOF'
export LAB_DATA_ROOT="/Users/Shared/lab-data/Database"
export LAB_OUTPUT_ROOT="/Users/Shared/lab-data/Output"
export LAB_INPUT_ROOT="/Users/Shared/lab-data/Input"
EOF
source ~/.zshrc

    Check it worked:

    ls "$LAB_DATA_ROOT/PublicDatabase/"
# should list AACR-GENIE, COSMIC, MSK-HEME, MSK-IMPACT …

    Restart Claude Code so it picks up the skills. Done.

Using it

Start Claude in whatever folder you want to work in:

cd ~/Documents/GitHub
claude

Then ask for what you want. You never name a tool — the right one loads from the question.

Not sure what is possible? Ask "what can you do here?" or "what data do we have?" and Claude will walk you through the toolkit, what each part answers, and how they chain together. Good first question.

Cohort questions. These need nothing from you; the public databases are already on the server.

How common is DNMT3A R882H in AML?

Pull every B-ALL variant in GENIE v17, ranked by patient count.

Which genes co-occur with TP53 in B-ALL, and which are mutually exclusive?

Human variant to mouse model, end to end.

Take the top 20 CH mutations by GENIE frequency and tell me
which ones can actually be modeled in mouse.

Design prime editing pegRNAs for the ones that can, with sensors.

Turn that into an IDT order for UPEC-tevo.

Screens and bench data. These need your files on the server.

Call hits for bone marrow and spleen from counts_ABE.txt, T0 baseline.

Did the edit work? The .ab1 traces are in this folder.

Make that a volcano for the paper, Nature single-column width.

Worth knowing

AACR-GENIE is controlled-access data

It sits on the server under a data use agreement that governs who may access it. It is there for our own approved work. Before sharing results derived from it outside the lab, or pointing anyone else at the machine, check that it is covered.

Long jobs keep running when you disconnect

Some analyses run for hours. Start one with nohup and it survives closing your laptop:

nohup python long_script.py > run.log 2>&1 &
tail -f run.log        # watch it; ⌃C stops watching, not the job

Don't write to the shared data

/Users/Shared/lab-data/ is readable by everyone and writable by Kexin only, on purpose — so no one's script can corrupt the reference data that every analysis depends on. Write your results into your own home directory.
